# 笔盒任务：Qwen3-30B，中间层，无记忆对比只开技能记忆

- **作业**：Hopper `672594`（interactive，1 GPU，7.5 分钟），代码 `ec460e2`。
- **任务**：`pen` 序列，10 个任务，`pen_2000`–`pen_2009`。每个任务把一支笔（14 × 1.2 × 1.2 cm）放进一个窄长、朝向随机的绿色笔盒（内部 15.5 × 4.5 cm）。笔的方向偏差超过约 13° 就会架在墙上放不进去。
- **条件**：无记忆、只开技能记忆，各跑一次。指令是明确的，用户记忆用不上。

## 与之前 mid 级实验的差别（如实说明）

- **沙箱**：这次放行了内置函数 `next`。之前的 mid 级 session 实验没有放行。先前的作业 `672547` 用旧沙箱跑了“无记忆”的前 5 个任务，结果 0/5，修复尝试大多因为 `next` 报错而浪费，于是按用户要求停掉重跑。那次的部分输出在 `../pen30b_20261017T135114Z_aborted/`。
- **`free_spots` 不再返回 `gripper_yaw`**：只返回放置位置，以及物体在该位置应有的长轴方向。夹爪要转多少由模型自己计算。API 文档里写明了“被夹住的物体随夹爪一起转”。
- **容器带朝向**：感知、相机检查、真实状态评分都在容器自身坐标系里判断。

## 脚本门控（不调用模型）

结果在 `../pengate_20261017T134222Z/`。

- 搬运时转到和笔盒对齐：4/4 成功。
- 不转：0/4，笔都架在墙上。
- 笔盒朝向感知误差 ≤1.4°，笔的朝向误差 <1°。

所以 primitive 本身能完成任务，难点确实在“对齐”这一步。

| 任务成功（GT） | 0/10 | 0/10 |
| 失败执行 | 30/30 | 30/30 |

## 失败原因

1. **第一次尝试：把物体朝向直接当成夹爪朝向。** 模型写 `carry_to(..., yaw=spot["object_long_axis_yaw"])` 或 `yaw=case["long_axis_yaw"]`。笔是横着夹的，夹爪方向和笔身垂直，结果笔和盒子长轴偏 88–90°，横架在盒子上。20 个任务里有 9 个的第一次尝试相机测得约 89°。正确做法只差一项，要加上抓取时“夹爪方向和笔方向之差”。
2. **反思给出的教训是错的。** 模型总结的“教训”多是“改成沿笔的长边夹”或“换抓取高度”。沿长边夹，笔长 14 cm，超过 8 cm 的手指间距，根本夹不住。于是修复尝试偏离了真正的原因。
3. **修复代码出错。**
   - 选不到候选时把 `None` 传给 `grasp`（`'NoneType' object is not iterable`，12 次）。这里有一个接口问题：`grasp(None)` 应该返回更清楚的错误。
   - 把 `free_spots` 返回的字典当成列表用（`KeyError: 0`）。
   - 用了被禁止的 `lambda`，或者把“教训”里的固定高度和角度直接写死。
4. **技能记忆没有用武之地。** 我们的技能记忆只从自己验证成功的执行里提取，10 个任务一次都没成功，所以“只开技能记忆”和“无记忆”完全一样。

## 结论

这个任务对 Qwen3-30B 来说太难了：它在中间层 API 上没能自己想出“夹爪方向 ≠ 物体方向”这个换算，现有的诊断反馈也没有引导它想出来。因此**这次实验没能证明技能记忆的作用**，只说明了“技能必须先被成功获得一次”这个前提。录像：`<条件>/<任务>/video.mp4`（结束时笔横在盒子上，或没被拿起）。
