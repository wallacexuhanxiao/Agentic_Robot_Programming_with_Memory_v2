# 笔盒任务：用户记忆与技能记忆（Qwen3-30B，中间层 API）

## 结论

在“把笔对齐放进窄笔盒”这个需要“怎么做”知识的任务上：

- **用户记忆**把用户说过的一句处理要求带到后续任务，成功率从 0/10 提到 4/10。
- **技能记忆**把第一次成功提取成验证过的技能，后续直接复用。和用户记忆一起开时达到 7/10，失败执行和 LLM 调用也最少。
- 只开技能记忆时，要看模型能不能先碰巧成功一次，两次运行分别是 2/10 和 0/10。

## 任务与设置

- **场景**：Robosuite/MuJoCo，Panda 机械臂。一支 14 × 1.2 × 1.2 cm 的笔，一个内部 15.5 × 4.5 cm、朝向随机的绿色笔盒。笔的方向偏差超过约 13° 就会架在盒墙上。
- **感知**：只用俯视 RGB-D 颜色分割，仿真真实状态只用于评分（GT）。
- **任务**：10 个笔任务（`pen_2000`–`pen_2009`），指令是 “Put the <colour> pen in the green pen case.”。
- **教学版序列**：开头多一个教学任务 `pen_teach_1999`，用户说：“From now on, whenever you put a pen in my pen case, turn the pen so that it lines up with the long side of the case before you lower it. Please put the blue pen in the green pen case now.”
- **模型**：Qwen3-30B-A3B-Instruct-2507（vLLM，bf16），所有角色都由它承担。每个子目标最多 3 次尝试。
- **代码**：`60f5dab`，加上 `submit.sh` 的队列选项。

## 发生了什么

- **用户记忆**：教学任务里那句话通过了证据检查（引文逐字出现在用户原话里，并带有 “From now on”），作为笔的长期处理要求存入 `user_memory.json`。之后每个笔任务，这句原话都会附在写代码的任务说明里。模型据此会主动用 `rotate_by` 对齐，例如 `user/pen_2002`：

  ```python
  carry_to(spot["x"], spot["y"], height=0.18, yaw=None)
  rotate_by(delta_yaw)   # delta_yaw = 笔盒长轴 - 抓取时笔的长轴
  ```

- **技能记忆**：“两种都开”在教学任务成功后，提取出技能 `place_on_zone_v1`，并在两个新笔盒布局上验证 2/2，之后复用 5 次，成功 4 次。技能的关键部分如下，角度都在运行时从感知读取：

  ```python
  delta_yaw = zone["long_axis_yaw"] - obj["long_axis_yaw"]
  carry_to(x, y, height=0.18, yaw=None)
  rotate_by(delta_yaw)
  ```

- **只开技能记忆（第 1 次）**：到 `pen_2006` 才碰巧第一次成功，用的是 API 说明里的写法 (b)。提取的技能在 `pen_2007` 复用成功。但这个技能里写死了 `pen_2006` 场景的笔朝向（`-1.335`），到 `pen_2009` 选错了抓取候选。第 2 次运行一次都没成功，没有技能可学。

## 失败原因

1. **把物体朝向当成夹爪朝向**（无记忆、只开技能记忆的主要失败）：`carry_to(..., yaw=笔盒长轴)` 让笔偏 90°，横架在盒上。API 说明里专门写了这个误区，模型的第一直觉仍然这样写。
2. **失败教训归因错误**：模型反复总结出“沿笔的长轴夹”“改抓取高度”这类教训，而沿长轴夹根本夹不住。教训验证机制会把多次无效的教训标成“没帮助”，但没法产生正确的教训。
3. **适用性检查过于保守**：`both/pen_2005`、`both/pen_2008` 的笔盒超出了以往成功覆盖的可达范围，技能被判成 `uncertain` 没有复用；模型现写的代码又偏了 24°–32°。
4. **复用时没抓起笔**：`both/pen_2009` 复用技能时，笔还留在桌上；之前 `skill/pen_2009` 也报过没抓住。疑似抓取候选的问题，还没核实。
5. **技能里写死场景角度**：`skill/pen_2009`。技能提取时只拦写死的坐标，没拦写死的角度。

## 实验过程中修复或改动的地方（如实记录）

| 改动 | 提交 | 原因 |
|---|---|---|
| 沙箱放行 `next` | `ec460e2` | 修复尝试大多因 `next` 不可用而浪费（之前 mid 级 session 实验没有放行） |
| 诊断加入“夹爪 yaw 对比物体朝向”的测量事实；教训记录后续结果，无效的标成“没帮助” | `0725c9f` | 失败教训归因错误，而且错误教训被反复带入后续任务 |

| 拿着东西时 `go_home()` 保持夹爪朝向 | `c687500` | `free_spots`/`check` 停开手臂时，会悄悄把手里的物体转掉 |
| `move_to` 等朝向也到位才返回 | `4ed61a4` | 大角度转动时提前返回，最多差约 50° |

每次改动后都在 Hopper 上用脚本门控验证过（不调用模型）：对齐脚本 4/4，不转 0/4，`rotate_by` 脚本 4/4，原 mid 门控 4/4（`results/pen30b_20261017T145010Z/`、`results/pengate_20261017T134222Z/`）。

## 注意事项

- 每个条件只跑了一次，只开技能记忆跑了两次。只开技能记忆的波动很大（2/10 对 0/10）。
- “无记忆”和“只开技能记忆”用的是普通序列，“只开用户记忆”和“两种都开”用的是教学版序列（多一个教学任务）。10 个笔任务的布局完全相同，但教学任务也给了技能记忆一次额外的学习机会。
- `672709` 所在的 interactive 节点很慢，模拟进程以 SIGABRT 崩溃了 3 次，都用 `--resume` 续跑了（`crashes.log`）。small 队列的作业没有崩溃。
- 用旧说明跑的几次笔盒实验都是 0/10，见 `pen30b_20261017T141514Z/`、`pen30b_20261017T145010Z/`（`rotate_by` 版，运动层修复前），以及 `pen30b_20261017T150043Z/`（运动层修复后，未下载）。
