# 中期演示视频：中间层 primitive + 双记忆（带同步代码面板）

- **视频**：`results/demo/mid_level_with_code.mp4`，3 分 16 秒，1040×368，20 fps。
- **来源**：实验 `results/mid30b_20261017T110309Z`（Qwen3-30B-A3B-Instruct-2507，mid 级 API），由 Hopper 作业 `672504` 确定性重放生成，重放结果在 `results/replaymid_20261017T124818Z/`。
- **重放方式**：按原种子、原程序、原技能代码重新执行，**不调用模型**。7 段重放的真实状态评分都和原运行一致（见各段 `replay.json`）。
- **关于 GraspNet**：原运行这 7 段从没收到过 Contact-GraspNet 候选，所以重放时关闭了 GraspNet，抓取候选和原运行完全相同。它的采样有随机性，开着的话重放会多出候选，见 `results/replaymid_20261017T123059Z/` 中 `tidy_1005` 不一致的那次。

## 画面说明

- **左边**：MuJoCo/Robosuite 里的 Panda 机械臂。顶部黑条显示任务编号和记忆条件。
- **右边面板**，从上到下：
  - 青色：任务编号、记忆条件、API 级别（mid-level API）。
  - 白色：用户的原话指令。
  - 当前子目标（物体 → 容器）和第几次尝试。尝试有两种来源：“code written by the LLM”表示模型现写的代码；“direct reuse of learned skill”（绿色）表示直接调用记忆里的技能，不生成新代码。
  - 青色 `Memory: ... judged APPLICABLE/UNCERTAIN`：技能记忆对这个子目标的适用性判断。
  - 正在执行的程序：**黄色高亮行**是机器人此刻在执行的那一行。进入技能内部时，标题会变成 `inside learned skill skills.<名字> (code from memory)`。
  - 青色 `returned:`：上一个 API 调用的返回值，例如抓取候选数量、`holding_something`、容器里有几个空位。
  - 绿色 `>`：正在执行的 API 调用。
  - 最底一行：每次尝试后的相机检查结果（绿色表示通过，红色表示未通过或程序报错）；每段最后是仿真真实状态评分（GT），这个评分不会给模型看。
- **容器**（模拟用户的长期偏好）：紫色底、灰色围墙的玩具箱放积木，青色托盘放杯子，橙色托盘放小本子。物体按“颜色_类别”命名，如 `red_block`、`yellow_mug`、`blue_book`。
- 开头两张说明卡：图例，以及中间层 API 的函数列表和“系统负责什么、模型决定什么”。

## 时间轴与讲解要点

| 时间 | 片段 | 讲什么 |
|---|---|---|
| 0:00–0:18 | 图例卡、中间层 API 卡 | 中间层介于 TidyBot 的 `pick_and_place` 和 ASPIRE 的位姿/点云之间：系统负责感知、抓取候选和运动执行，模型决定选哪个抓取、放在哪里、朝向、松手时机、顺序和恢复 |
| 0:18–0:43 | `teach_4`，两种记忆 | 用户说“以后积木放紫箱、杯子放青托盘、书放橙托盘”。用户记忆存下规则；模型用中间层 primitive **现写代码**完成两个物体，成功后提取为技能 |
| 0:43–1:09 | `tidy_1004`，两种记忆 | 模糊指令“Put my things where they belong.”。目标来自用户记忆；两个子目标都**直接调用已学技能**，不生成新代码，GT 成功 |
| 1:09–1:26 | `tidy_1004`，无记忆 | 同一个任务。模型现写的代码对 `free_spots` 返回值用错了键（`'occupants'`），积木连续 3 次失败，GT 失败。对比上一段：技能复用避开了现写代码出错 |
| 1:26–1:52 | `tidy_1005`，两种记忆 | “Tidy up my desk, please.”。目标来自用户记忆，两次调用技能，GT 成功 |
| 1:52–2:07 | `tidy_1005`，无记忆 | 没有用户记忆，模型只能猜：把积木放到了青色托盘（应该放进紫箱），也没处理杯子。动作本身执行成功，但目标错了，GT 失败。说明用户记忆决定了“放哪” |
| 2:07–2:47 | `tidy_1002`，两种记忆 | 杯子靠技能复用。中间那个 `yellow_book` 是**感知误检**（托盘边缘被识别成一本书，宽度为 0），3 次都抓不到。第三个子目标里，书在两次代码报错后，第 3 次根据反馈修正成功。GT 成功（误检的“书”不在真实目标里） |
| 2:47–3:16 | `tidy_1003`，两种记忆（失败例子） | 书在带围墙的玩具箱里，抓取下降被箱壁挡住（`motion_blocked`）。之后技能抓起积木，但紫箱被书占着，没有空位，技能直接返回，积木一直拿在手里。这暴露了两个问题：模型自报“容器被占也能用”的技能条件不可靠；书困在箱里的抓取局限，task 级也有 |

## 讲解时要如实说明

- 这是单次运行（每个条件 10 个任务）。mid 级有用户记忆时 8/10、无记忆 5/10；task 级同一模型是 9/10 和 4/10；pose 级是 0/26。
- 技能记忆在 mid 级让很多子目标不用再写代码，但效率提升不如 task 级明显：失败执行“两种记忆”14 次对“只开用户记忆”15 次。
- 感知是俯视 RGB-D 颜色分割，不是 SAM3；仿真真实状态只用于评分。
- 原实验作业中模拟进程崩溃过，后半段任务用 `--resume` 在新作业里补跑，见 `results/mid30b_20261017T110309Z/README_zh.md`。
