# 技能记忆省下的 LLM 调用省在哪里（2026-11-12）

老师的问题：技能记忆能减少 LLM 调用，那减少的是哪些调用？在什么情况下会出现可以复用的重复？

- **数据**：已有的技能记忆 vs 无记忆配对运行，两组跑的是同一批桌子。没有新跑实验，不花钱。
- **方法**：每次 LLM 调用按日志里记的用途分类；每个物品的工作量（尝试次数、新写的程序数、直接复用技能的次数、第一次就成功的次数）从 `episode.json` 里数。
- **重算**：`python3 scripts/llm_savings.py`，数字写到 `results/dev_stats/llm_savings.json`。
- **图**（英文，可直接放 PPT）：`docs/figures/dev/llm_calls_by_purpose.png`、`docs/figures/dev/llm_calls_by_object.png`。

## 1. 一张桌的 LLM 调用由什么组成

| 用途 | 什么时候调用 | 次数 |
|---|---|---|
| 识别（identify） | 每张桌开头，SAM2 桌才有 | 1 |
| 推断去处（refine） | 每张桌开头 | 1–2 |
| 规划（plan） | 每张桌开头 | 1 |
| 重新规划（replan） | 有子目标失败、需要换顺序时 | 0–数次 |
| 写程序（code） | 每个子目标的每次尝试；直接复用技能时不调用 | 每次尝试 1 |
| 失败后反思（reflect） | 每次尝试失败后，写一条教训 | 每次失败 1 |
| 提炼技能（extract） | 新程序成功后，把它存成技能 | 0–1 |

技能记忆只作用在"每个物品的尝试循环"上，也就是写程序、反思、重新规划这三项。

## 2. 省在哪些调用上

每张桌的平均调用次数：

| 设置 | 桌数 | 无记忆 | 技能记忆 | 写程序 | 反思 | 重新规划 | 提炼（新增开销） | 识别 / 推断去处 / 规划 |
|---|---|---|---|---|---|---|---|---|
| Gemini 颜色感知 | 20 + 20 | 17.8 | **9.8** | 8.55 → 4.05 | 5.90 → 2.65 | 1.20 → 0.50 | 0 → 0.45 | 不变 |
| Gemini + GraspNet/cuRobo | 10 + 10 | 22.5 | **11.5** | 10.6 → 4.1 | 8.1 → 3.0 | 1.7 → 0.8 | 0 → 1.5 | 不变 |
| DeepSeek SAM2 | 3 + 3 | 39.3 | **26.0** | 24.3 → 14.0 | 7.0 → 5.0 | 4.0 → 1.7 | 0 → 1.3 | 不变 |
| DeepSeek 新桌面新物品 | 3 + 3 | 45.3 | 47.0 | 19.3 → 19.3 | 11.0 → 12.0 | 11.0 → 9.3 | 0 → 2.3 | 不变 |

- 以 Gemini 20+20 为例，每桌省下 8 次调用：写程序省 4.5 次，反思省 3.25 次，重新规划省 0.7 次，提炼多花 0.45 次。
- 每张桌开头的识别、推断去处、规划，有没有技能记忆都一样。技能记忆管不到"这张桌上有什么、该放哪"这类每张桌都要重做的推理。
- 学习是有开销的：每成功一个新程序，要多一次提炼调用。在新物品上这笔开销没有被复用收回，所以新桌面上反而多了 1.7 次。

## 3. 省在哪类物品上

把"写程序 + 反思"的调用按物品类别分开，结果见 `llm_calls_by_object.png`，表中百分比是各类物品占这部分节省的比例：

| 设置 | 每桌省下的"写程序+反思" | 笔（竖插笔筒） | 杯子 | 纸团 | 其他 |
|---|---|---|---|---|---|
| Gemini 颜色 20+20 | 7.75 | **77%** | 11% | 12% | 小书 −1%，积木 1% |
| Gemini + GraspNet/cuRobo 10+10 | 11.6 | **63%** | 9% | 13% | 小书 15% |
| DeepSeek SAM2 3+3 | 12.0 | **69%** | 25% | −11% | 本子 17% |

Gemini 20+20 上各类物品的情况：

| 物品 | 无记忆：每桌调用 / 第一次就成功 | 技能记忆：每桌调用 / 第一次就成功 | 直接复用技能 |
|---|---|---|---|
| 笔 → 竖插笔筒 | 8.0 / **0/28** | 2.0 / **13/19** | 8 次，全部成功 |
| 纸团 → 废纸篓 | 2.8 / 11/19 | 1.9 / 10/18 | 11 次，成功 7 |
| 杯子 → 杯垫 | 1.7 / 14/19 | 0.8 / 13/18 | 13 次，成功 9 |
| 小书 → 托盘 | 0.8 / 17/17 | 0.9 / 16/17 | 1 次 |
| 积木 → 盒子 | 1.2 / 0/4 | 1.1 / 0/4 | 2 次，成功 0 |

## 4. 结论：哪种重复能用上记忆

1. **难的子任务在多张桌上反复出现，省得最多。**
   - 把笔竖着插进笔筒需要转姿态，模型很难一次写对。
   - 没有记忆时，每张桌都要从头试，第一次从来不成功（0/28），每支笔平均失败约 3 次，每次都是"写程序 + 反思"两次调用。
   - 有了存好的笔技能，直接调用，大多数第一次就成功。
   - 三组实验里，这一项占了省下调用的 63–77%。省下的主要是反复试错的循环，而不只是一次写代码。
2. **常规子任务重复出现，每次省约一次写程序。**杯子放杯垫、纸团进废纸篓，没有记忆也大多一次成功；有记忆时直接调用技能，省掉写那一段程序。
3. **以下几种情况省不了：**
   - 很容易的任务：小书放托盘，没有记忆也一次就成功。
   - 从没成功过、记忆里没有技能的任务：本子在 DeepSeek SAM2 两组都是 3 次全失败；新桌面上的新物品。
   - 每张桌开头的识别、推断去处、规划：这些每张桌都要重做，技能记忆不涉及。

一句话：**技能记忆省下的，主要是难的、会在多张桌上重复出现的操作子任务的试错循环；这类重复越多、没有记忆时越容易失败，省得越多。**

## 5. 注意

- Gemini 两组的技能记忆是从更早的运行继承来的，不是从空记忆开始。所以这里看不出"从零开始学"的曲线，看到的是"已经学会之后"的节省。
- 无记忆组的子目标更多（例如 28 对 19 个笔子目标），因为失败的子目标会被重新规划，再排一次。表中"每桌调用"已经把这部分算进去了。
- DeepSeek 两组各只有 3 张桌，样本小。
- 新桌面那一组只是说明适用边界：物品大多是新的，记忆里还没有它们的技能。

## 6. 具体到程序里的哪一步

脚本：`python3 scripts/api_steps.py`，数字写到 `results/dev_stats/api_steps.json`。

每次尝试的沙箱 trace 记录了程序调用的每个 API，按阶段归类：

| 阶段 | API |
|---|---|
| 抓取候选 | `grasp_candidates`：几何法；开了服务时还有 Contact-GraspNet |
| 抓 | `grasp` |
| 转姿态（6 自由度） | `solve_ik`、`move_gripper`、`rotate_by` |
| 搬运 | `carry_to`：直线；开了 cuRobo 时用 cuRobo 规划 |
| 下降放置 | `lower_until_contact`、`move_by`、`open_gripper` |

下面的数据来自前三组配对运行（技能记忆 vs 无记忆）。

### 6.1 笔：重复出现、又最难重新想出来的是"转姿态"这一步

图：`docs/figures/dev/pen_reorientation.png`（英文）。

| | 无记忆 | 技能记忆 |
|---|---|---|
| 尝试次数，成功 | 149 次，成功 7 次（5%） | 52 次，成功 24 次（46%），其中 13 次直接调用技能 |
| 程序里有"转姿态"这一步 | **27/149（18%）** | **29/52（56%）** |
| 有转姿态时成功 | 4/27（15%） | **22/29（76%）** |
| 没有转姿态时成功 | 3/122 | 2/23 |
| 失败在哪 | 程序跑完但结果不对 74 次（笔横搭在筒口或没竖起来）；抓取阶段被挡 43 次 | 跑完但结果不对 16 次；抓取阶段 11 次 |

- 没有记忆时，82% 的程序根本没有转姿态这一步，只是把横着的笔搬到笔筒上方松手，所以几乎不可能成功。
- 少数写了转姿态的，也大多不成功，比如 IK 够不着、转的方向不对。
- 存下的笔技能 `place_on_zone_v7` 由 3 个 helper 组成：
  1. `grasp_elongated_object`：横着抓住笔，抓取高度不低于 1.2 cm；
  2. 搬到筒口上方 15 cm，再调 `reorient_held_object_upright`：在 4 个水平进入方向里用 `solve_ik` 找一个够得着的，用 `move_gripper` 把手转平，让笔竖直垂在手下面；
  3. `drop_into_container_v2`：松手，后退。
- 记忆存下来的，是"要转姿态"这件事，加上转姿态的具体做法和参数：多高、哪几个方向、先试哪个。这正是没有记忆时每张桌都要重新摸索、反复失败的部分。

### 6.2 杯子、纸团、小书：重复的是整段"抓—搬—放"，记忆省的是重写程序

这几类不需要转姿态，成功的程序都是同一个顺序：

`grasp_candidates → grasp → carry_to → lower_until_contact（或直接松手）→ open_gripper → retreat`

| 物品 | 每次尝试的成功率（无记忆 → 技能记忆） | 技能记忆组直接调用技能 | 抓取阶段失败（无记忆 → 技能记忆） |
|---|---|---|---|
| 杯子 | 26/52（50%）→ 28/44（64%） | 44 次里 19 次 | 13 → 6 |
| 纸团 | 26/62（42%）→ 25/57（44%） | 57 次里 21 次 | 19 → 18 |
| 小书 | 26/39（67%）→ 26/38（68%） | 38 次里 8 次 | 7 → 4 |

- 这段顺序每张桌都一样，没有记忆时模型每次都要重写一遍，通常也写得对。
- 有记忆时直接调用存好的技能或 helper，比如 `place_at_position`、`drop_into_container`、`pick_object_with_candidates`，省掉一次写程序。
- 成功率基本不变，抓取时被旁边东西挡住这类失败也没少。记忆在这里省的是推理，不是失败。

### 6.3 GraspNet 和 cuRobo 本身不是省调用的地方

- **抓取候选**：程序大多选几何法给的候选；无记忆组笔的 126 次抓取里，105 次用的是几何候选。Contact-GraspNet 的候选被选中的次数不多（笔：无记忆 21 次，技能记忆 5 次），样本太小，看不出选它是好是坏。这一步每个程序都会调用，有没有记忆都会用，记忆没有改变它。
- **cuRobo**：在搬运时用于规划。搬运阶段很少出错：配对运行里 0–3 次；全部 act 层运行中，笔 648 次尝试里只有 9 次。所以这里没有需要靠记忆弥补的试错。
- **最常见的运动失败**是 `motion_blocked`，大多发生在抓取下降时手指碰到旁边的东西。两组都有，记忆没有减少它。这是物理和布局问题，不是推理问题。

### 6.4 一句话回答

记忆省下的调用，主要来自两种重复：
1. **6 自由度的转姿态步骤**：`solve_ik` 搜索方向加 `move_gripper` 转到竖直。它很难，又在每张有笔的桌上重复出现，没有记忆时 82% 的程序漏掉它。这一项占节省的大头。
2. **常规的"抓—搬—放"整段程序**：每张桌都一样，记忆让它不必重写，每次省一次调用。

GraspNet 选抓取点、cuRobo 规划搬运路线，这两步每个程序都会调用，但它们不是试错的来源，记忆在这两步上省不了什么。
