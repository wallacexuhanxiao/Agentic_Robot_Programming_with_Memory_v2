# Harness 更新（2026-11-04）：可组合的子技能，长程执行监控与重新规划

## 1. 可组合的子技能（helper）

**为什么要加：** 之前一个技能就是"一整段完成某个子目标的程序"，更像是缓存了一次成功的解法，不能拿去组合，也很难迁移到别的任务。

**提取：** 一段新写的程序通过相机检查后（`extract_skill`，提示词 `prompts.EXTRACT`），模型需要做两件事：
1. 把程序拆成 2–4 个 helper 函数。每个 helper 是能单独成立、也能在别的任务里复用的一步，比如：
   - 选一个抓取方式并执行；
   - 把手里的物体转到某个朝向；
   - 搬到某处，放下或插入。

   每个 helper 要用参数代替场景里的具体数值，并写一行说明：执行前需要满足什么，执行后会怎样。
2. 再写一个子目标函数 `place_on_zone_vN(obj_name, zone_name)`，由它去调用这些 helper。

提取时，记忆里已有的 helper 会列给模型，可以直接调用，不必重写。

**存储：**
- helper 单独存在技能记忆的 `helpers` 列表里，每条包含名字、代码、说明、适用物体类别、来源、历史和状态。
- 同名但代码不同的 helper 会加版本后缀，调用它的地方会一起改名。
- 同名且代码相同的 helper 不会重复存；这时把新的物体类别并入它的适用类别。

**调用：**
- 所有可用的 helper 都会注入沙箱，程序和技能都可以直接按名字调用。
- 每次调用都会记进执行轨迹，记作 `helpers.<名字>`。

**记录：** helper 被调用的那次尝试（包括新布局验证）成功或失败，都会写进它的历史。
- 有 2 次成功即为"已验证"，有 1 次成功为"候选"。
- 0 次成功、累计失败 3 次即为"已拒绝"，之后不再提供。

**写代码时：** 和当前物体类别相关的 helper（签名、说明、状态、历史成败）会列给模型，并提示它优先拼装这些 helper，而不是重写这些步骤。

**指标：** `summary.json` 新增两项：
- `helper_calls`：helper 被调用的次数；
- `replans`：重新规划的次数。

## 2. 长程任务的执行监控与重新规划

**初始规划：** 规划提示词里加上相机看到的"每个容器里现在有什么"。

**每个子目标之后：** `env.check_goals` 只收一次手臂、拍一次照，就检查所有目标，得到三类信息：
- 哪些目标已经完成；
- 哪些原本完成、又被碰乱了；
- 还剩哪些目标。

**重新规划：** 以下三种情况会调用 `prompts.REPLANNER`，重排剩下的步骤：
- 子目标失败；
- 有已完成的目标被碰乱；
- 原计划里剩下的物体和实际剩下的不一致。

重新规划时提供给模型的信息有：已完成的目标、剩余目标、上一步结果、之前的失败原因、各容器里现在有什么、当前场景。
- 模型漏掉的目标会自动补在计划末尾。
- 每个目标最多执行 2 轮，总步数不超过目标数的 2 倍加 1。

**记录：** `episode.json` 新增两项：
- `progress`：每一步之后的检查结果；
- `replans`：每次重新规划的原因和新计划。

## 同一轮里的其他修正

- **cuRobo 可行性检查**改用 `/plan` 接口。服务端的 `/ik` 接口在初始化碰撞模型时出错，每次都返回 500。
- **几何抓取候选的分数**改成固定数值：横夹短边 0.5，横夹长边 0.3。之前是空值，模型按分数排序时会报错。
- **物体名字保持不变：** 物体按颜色保留第一次看到时的名字。之前笔被碰歪后会被识别成别的类别，名字跟着变了。
- **容器位置：** 容器被手臂挡住时，沿用之前看到的位置。
- **验证器收手臂：** 收手臂失败时先走关节空间回到初始位姿；还不行，就在当前位置直接拍照判定，不再中断整个任务。
- **沙箱**允许使用 `lambda`。
- **技能新版本：** 存下的技能复用失败、随后修复成功时，修复后的程序存成新版本，旧版本标记为 `superseded`，不再被检索到。
- **跨运行继承技能：** `SMA_MEMORY_INIT` 可以指定一份已有的技能记忆作为初始记忆。
- **任务数：** 笔筒和整理任务默认每组 5 个任务，由 `SMA_SUITE_SIZE` 控制。

## 验证

- **本地逻辑测试：** 用一个假的机器人和预设回复的 LLM 走完了整个流程，没有跑仿真。依次验证了：
  - 第一次放置失败后修复，成功后提取出两个 helper；
  - 下一步把已完成的物体碰乱，被监控发现并触发重新规划，物体被重新放好；
  - 下一个任务的程序调用了这两个 helper。
- **Hopper 上的实验：** 整理任务，无记忆对比技能记忆。技能组继承笔筒任务学到的技能记忆。
